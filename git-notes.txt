я вернулась в состояние где я только создала первый коммит то есть ридми

git restore - возвращает файл к последнему закоммиченному состоянию
git checkout <хеш> - переключает рабочую папку на состояние какого либо коммита
что такое HEAD detached - используют когда нужно посмотреть или проверить старое состояние проекта, ничего не ломая в ветках
git revert - создаёт новый коммит, который отменяет изменения выбранного коммита, а историю не переписывает 
git switch -c это создать новую ветку
git merge - это соединить две ветки
что такое fast-forward - ветка просто передвигается вперёд, без лишнего коммита
git branch -d это удалить какую либо ветку
merge request это просьба добавить изменения из своей ветки в main
ревью нужно чтобы другой человек посмотрел изменения и заметил ошибки

второй merge request получил конфликт потому что мы оба изменили одну и ту же строку в README
после слияния первой ветки git не смог сам выбрать какую версию оставить

сначала мы перешли в main и скачали обновления
потом вернулись в свою ветку и выполнили git merge main
открыли README оставили общий заголовок и удалили маркеры конфликта
сохранили файл добавили его через git add сделали коммит и выполнили git push

Что такое конфликт слияния в Git и когда он возникает?
когда два человека например один написал Хай в своей ветке а другой Привет и хотят слитьв главную ветку, гит не может выбрать какой либо вариант и просить выбрать человека.
